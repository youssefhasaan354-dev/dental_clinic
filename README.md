# عيادة حياة لطب الأسنان — Hayaah Dental Clinic
### نظام الحجز الإلكتروني المتكامل ولائحة الإدارة الطبية
**Full Appointment Booking System + Staff Admin Dashboard**

مبني باستخدام: **React 18**, **Vite**, **Framer Motion**, **date-fns**, **date-fns-tz**, **Bootstrap 5 / Sass**, **Supabase Client**, **Vitest**.

## 🌟 نظرة عامة | System Overview

تم بناء وتوسيع هذا النظام ليقدم تجربة حجز مواعيد سريرية حقيقية خالية تماماً من تضارب المواعيد (Conflict-Free Live Booking Engine) مع لوحة تحكم إدارية محمية لكادر العيادة.

### 🔑 أهم الميزات المكتملة:
1. **معمارية بيانات موحدة (Data-Access Layer)** في `src/services/booking/`:
   - واجهة موحدة `IBookingService`.
   - **Demo Adapter (افتراضي)**: يعمل فورياً داخل المتصفح عبر `localStorage` مع مخزن احتياطي بالذاكرة وبدون أي إعدادات خارجية، ومزود بـ ٤٠ موعداً تجريبياً واقعياً موزعاً على ٣ أسابيع.
   - **Firebase / Cloud Firestore Adapter**: قاعدة بيانات سحابية متكاملة (Firebase Auth + Firestore Security Rules + قفل الفترات الحتمي لمنع الحجز المزدوج + فصل جداول مواعيد العمل `doctor_schedules` عن ملفات المحتوى الترويجي `doctors`).
2. **محرك فترات ذكي وآمن زمنياً (Timezone-Safe Slot Engine)**:
   - يحسب المواعيد حصرياً بتوقيت القاهرة (`Africa/Cairo`) بغض النظر عن موقع جهاز الزائر ومراعاة التوقيت الصيفي (DST).
   - إغلاق تام وتلقائي لأيام الجمعة (العيادة مغلقة الجمعة).
   - ساعات العمل: السبت–الخميس من ١٠:٠٠ ص إلى ١٠:٠٠ م.
   - منع الحجز في نفس اليوم إلا بمهلة ساعتين مسبقاً على الأقل (`minNoticeHours: 2`).
   - أقصى حجز مسبق ٦٠ يوماً.
   - منع الحجز المزدوج: فحص التضارب التزامني قبل الحفظ وفي مستوى قاعدة البيانات.
   - التحقق الصارم من صحة وتنسيق أرقام الهواتف المصرية (010, 011, 012, 015, وأرضي 02).
3. **معالج حجز تفاعلي متعدد الخطوات (Public Booking Wizard)**:
   - الخطوة ١: اختيار الخدمة (١٢ خدمة بالإضافة لكشف عام).
   - الخطوة ٢: اختيار الطبيب (أي طبيب متاح، أو طبيب محدد).
   - الخطوة ٣: تقويم مخصص وشبكة مواعيد مقسمة (صباحاً / بعد الظهر / مساءً) مع توضيح فوري للمواعيد الشاغرة والمحجوزة.
   - الخطوة ٤: بيانات المريض والتحقق من الهاتف، وتحديد مريض جديد أو سابق، وحقل مضاد للسبام (Honeypot)، وموافقة الخصوصية.
   - الخطوة ٥: مراجعة كاملة لملخص الحجز وإرسال آمن.
   - الخطوة ٦: بطاقة النجاح مع **كود حجز فريد** (مثل `HAY-4F7K2`)، زر إضافة لتقويم الهاتف وتنزيل ملف `.ics` ورابط Google Calendar، وزر فتح واتساب العيادة المباشر برسالة مجهزة، وزر طباعة القسيمة.
4. **صفحة إدارة الحجز للزوار (`/booking/manage`)**:
   - إدخال كود الحجز + الهاتف -> عرض بيانات الحجز.
   - إمكانية إعادة الجدولة (تعديل اليوم والوقت عبر نفس المحرك).
   - إمكانية الإلغاء مع احترام مهلة الإلغاء (مهلة ٣ ساعات قبل الموعد).
   - مستبعدة من محركات البحث والفهرسة (`noindex`).
5. **لوحة إدارة العيادة المحمية (`/admin`)**:
   - تسجيل دخول تجريبي بنقرة واحدة، بالإضافة لبيانات الدخول التجريبية أو Supabase Auth.
   - **لوحة المؤشرات (Overview)**: بطاقات KPI تفاعلية، رسم بياني SVG لحركة الحجوزات خلال ١٤ يوماً، رسم بياني لأكثر الخدمات طلباً، وقائمة المواعيد القادمة.
   - **إدارة المواعيد (Appointments)**: عرض جدول + عرض تقويم (يومي/أسبوعي/شهري)، فلترة بالبحث والتاريخ والطبيب، إجراءات سريعة لتأكيد واكتمال الحجز، إجراءات جماعية، وإنشاء حجز فوري للمرضى الحاضرين لمقر العيادة (Walk-in)، وتصدير ملف Excel/CSV بترميز UTF-8 BOM الداعم للعربية 100%.
   - **سجل المرضى (Patients)**: دليل بجميع المرضى وعدد زياراتهم وتاريخ آخر كشف، مع نافذة جانبية لتاريخ الزيارات، وخيار لحذف السجل احتراماً لخصوصية المريض.
   - **الأطباء وجدول العمل (Doctors & Schedule)**: إدارة الأطباء، ساعات العمل الأسبوعية لكل طبيب، وحظر الفترات والاستراحات (مثل استراحة الغداء ١٣:٠٠ - ١٤:٠٠) والعطلات الرسمية.
   - **إعدادات الحجز (Booking Settings)**: تخصيص مدة الكشف، مهلة الحجز، مهلة الإلغاء، أوقات الفتح والإغلاق، تفعيل التأكيد التلقائي، وتعديل قوالب رسائل الواتساب.

## ⚙️ التبديل إلى قاعدة بيانات Firebase و Firestore الحقيقية (Step-by-Step)

النظام يعمل تلقائياً بوضع Demo Mode في حال عدم توفر متغيرات Firebase. لتفعيل الربط السحابي الحقيقي:

1. أنشئ مشروعاً جديداً مجانياً على [Firebase Console](https://console.firebase.google.com).
2. فعّل قاعدة بيانات **Cloud Firestore** بوضع الإنتاج (**Production Mode**).
3. فعّل **Firebase Authentication** وافتح موفر **Email/Password**.
4. أضف مستخدم المشرف الأول في Authentication، ثم أنشئ مستنداً في Firestore ضمن مجموعة `admins` بالمعرف الخاص به `admins/{uid}` وضع حقلاً `role: "owner"`.
5. انشر قواعد الأمان والفهارس باستخدام `firebase deploy --only firestore:rules,firestore:indexes` أو بالنسخ المباشر من [firestore.rules](firestore.rules) و [firestore.indexes.json](firestore.indexes.json).
6. أنشئ ملف `.env` محلياً وفي Vercel (مستوحى من `.env.example`) وضع المتغيرات الأربعة:
   ```bash
   VITE_FIREBASE_API_KEY=AIzaSy...
   VITE_FIREBASE_AUTH_DOMAIN=hayaah-dental.firebaseapp.com
   VITE_FIREBASE_PROJECT_ID=hayaah-dental
   VITE_FIREBASE_APP_ID=1:1234567890:web:abcdef123456
   ```
7. أعد تشغيل السيرفر (`npm run dev`). سيكتشف تطبيق الويب المفاتيح تلقائياً ويتحول من وضع Demo Mode إلى وضع Firebase السحابي المباشر.

## 🛡️ الحماية الفعلية قبل الإطلاق: تفعيل Firebase App Check مع reCAPTCHA و Enforcement

> [!IMPORTANT]
> **تنبيه أمني هام بشأن حماية الحجوزات:**
> آلية الحد من التردد المحلية (Client-Side Throttle عبر `localStorage`) هي مجرد طبقة مساعدة لتجربة المستخدم (UX Helper) لتفادي تكرار الضغط بالخطأ، **وليست حماية أمنية حقيقية** لأن أي شخص يمكنه تجاوزها بسهولة عبر أدوات برمجية أو نافذة التصفح الخفي.
> **الحماية الحقيقية والملزمة قبل الإطلاق العام للعيادة هي تفعيل Firebase App Check مع reCAPTCHA وفرض الرقابة الإلزامية (Enforcement) على Cloud Firestore.**

### خطوات تفعيل حماية App Check بالترتيب:
1. **إنشاء مفتاح reCAPTCHA:** من كونسول [Google reCAPTCHA](https://www.google.com/recaptcha/admin) أنشئ مفتاحاً بنوع **v3** (أو **Enterprise**) لنطاق العيادة المعتمد (مثل `dentallclinic.vercel.app`).
2. **تسجيل التطبيق في Firebase Console:** انتقل إلى **Build -> App Check -> Apps** وسجل تطبيق الويب الخاص بك مع إدخال المفتاح السري (**Secret Key**) المطابق لنوع المزود.
3. **ضبط المتغيرات البيئية في استضافة Vercel:**
   ```bash
   VITE_RECAPTCHA_SITE_KEY=6Ld...site_key_here
   VITE_RECAPTCHA_PROVIDER=v3   # أو enterprise إذا تم اختيار Enterprise في الكونسول
   ```
4. **مراقبة الطلبات الموثقة (Monitor Mode):** بعد النشر، اترك App Check في وضع المراقبة (بدون تفعيل الفرض) لمدة أسبوع تقريباً عبر تبويب **App Check -> APIs** للتأكد من أن جميع طلبات المرضى الشرعيين تظهر كطلبات موثقة (`Verified Requests`) بنسبة قريبة من 100%.
5. **تفعيل الفرض الإلزامي (Enable Enforcement):** من كونسول **App Check -> APIs -> Cloud Firestore** اضغط على **Enforce**. بعد هذه الخطوة، سيرفض Firestore أي اتصال قادم من خارج تطبيق الويب المعتمد أو عبر برمجيات السبام، مما يحمي قاعدة البيانات والحجوزات بنسبة 100%.

## 🔒 سياسة أمان المحتوى (CSP) وكيف نحولها إلى إلزامية (How to Enforce CSP)

تطبيق العيادة مهيأ بسياسة أمان محتوى حديثة ومضبوطة بدقة في ملف [vercel.json](vercel.json). حالياً تم ضبطها كوضع تقرير استطلاعي (**`Content-Security-Policy-Report-Only`**) لتفادي حجب أي خطوط أو مصادر وسائط أثناء مرحلة المراجعة والمعاينة:
- تدعم نطاقات خطوط جوجل (`fonts.googleapis.com` و `fonts.gstatic.com`).
- تدعم وسائط ومقاطع الفيديو من YouTube و Vimeo و Cloudinary.
- تدعم خدمات توثيق وحماية Firebase Auth و reCAPTCHA (`*.google.com`, `*.gstatic.com`, `recaptcha.google.com`, `identitytoolkit.googleapis.com`, `securetoken.googleapis.com`).
- تدعم دومينات التحليلات الخفيفة (`https://plausible.io`, `https://www.googletagmanager.com`, `*.google-analytics.com`, `*.analytics.google.com`).

### خطوات تحويل CSP إلى سياسة إلزامية (Enforced Mode):
1. **مراقبة تقارير التصفح لمدة أسبوع:** بعد إطلاق الموقع على Vercel Preview/Production، افتح كونسول المتصفح (DevTools Console) على أجهزة مختلفة (Desktop و Mobile) وتصفح مسار الحجز والإدارة للتأكد من عدم تسجيل أي تنبيهات `[Report Only]` لانتهاك سياسة CSP.
2. **استبدال اسم الترويسة:** افتح ملف `vercel.json` واستبدل سطر الترويسة:
   ```json
   "key": "Content-Security-Policy-Report-Only"
   ```
   ليصبح ترويسة أمان إلزامية:
   ```json
   "key": "Content-Security-Policy"
   ```
3. **النشر والتحقق:** أعد نشر المشروع إلى Vercel. ستقوم الترويسة الآن بمنع وحظر أي حقن كودي (XSS) أو سكربتات غير مصرح بها على مستوى المتصفح مباشرة.

## 📦 النشر على Vercel أو Netlify | Production Deployment

المشروع مهيأ بملفي `vercel.json` و `public/_redirects` لدعم التوجيه السلس لـ React Router:

1. اربط مستودع Git بـ **Vercel**.
2. في إعدادات **Build & Output Settings**:
   - Build Command: `npm run build`
   - Output Directory: `dist`
3. في حال تفعيل Supabase على الإنتاج، أضف المتغيرين في **Environment Variables**:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. اضغط **Deploy**.

## 🌐 متغيرات البيئة وإعدادات الفهرسة والـ SEO | Environment Variables & SEO

يحتوي ملف `.env.example` على كافة المتغيرات المدعومة:

| المتغير | القيمة الافتراضية | الوصف |
| :--- | :--- | :--- |
| `VITE_SITE_URL` | `https://dentallclinic.vercel.app` | النطاق الأساسي المعتمد للموقع (بدون شرطة مائلة). يُستخدم لبناء روابط Canonical وتوليد `sitemap.xml` و `robots.txt` وروابط OG المطلقة. |
| `VITE_ALLOW_INDEXING` | `false` | صمام أمان الفهرسة؛ الافتراضي `false` يمنع عناكب البحث (`noindex, nofollow` و `Disallow: /`). اضبطه على `true` عند موافقة العيادة على الإطلاق. |
| `VITE_DEMO_MODE` | `true` | وضع المعاينة التفاعلي الافتراضي (Zero-Config بدون خادم خلفي). |
| `VITE_ADMIN_DEMO_LOGIN` | `true` | إظهار صندوق وبيانات الدخول التجريبي بنقرة واحدة في `/admin/login`. يُنصح بضبطه على `false` في الإنتاج لإخفاء الحسابات التجريبية وتعطيلها تماماً. |
| `VITE_HIDE_DEMO_BANNER` | `false` | إخفاء شريط التنبيه بوضع التجربة (Demo Banner) في معالج الحجز؛ الافتراضي يظهره لحماية المرضى من الحجز الوهمي. |
| `VITE_CLINIC_WHATSAPP` | *(اختياري)* | رقم واتساب مباشر للعيادة بصيغة دولية (مثل `201012345678`) يتجاوز رقم الأرضي الافتراضي. |
| `VITE_FIREBASE_*` | *(اختياري)* | مفاتيح الربط بقاعدة بيانات Cloud Firestore الحقيقية. |
| `VITE_ANALYTICS_ID` | *(اختياري)* | معرف تحليلات خصوصية خفيف (مثل Google Analytics / Plausible) دون تتبع بيانات المرضى الشخصية. |
